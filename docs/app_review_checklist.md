# Meta App Review 準備清單

> 這份是「**未來真的要走 App Review 時**」的完整準備清單。現階段不必交件，但可以慢慢累積。
>
> 完成後，App 從「Development（開發）模式」→ 「Live（上線）模式」，webhook 才會收到真實留言通知。

---

## 階段 0：交件前先做這個決策

打 ✅ 才繼續往下走：

- [ ] 我有明確的商業化計畫（諮詢服務、課程、SaaS 等）
- [ ] 我願意花 1-3 個月時間 + ~NTD 3,000 規費 + 心力
- [ ] 我接受 60-70% 第一次被退件的可能
- [ ] 我有商業實體（公司 / 行號），或願意申請

如果勾不到 3 個 → **現階段不該走**，用 polling 即可。

---

## 階段 1：個人能做、零成本、可立刻準備（總計 5-10 小時）

### 1.1 App 圖示

| 規格 | 說明 |
|---|---|
| 尺寸 | 1024 × 1024 px（必須正方形） |
| 格式 | PNG，建議帶透明背景 |
| 內容 | 不可含 Meta、Facebook、Instagram、Threads 任何 logo |
| 風格 | 跟你品牌一致（依領域決定：專業、親和、信任感、知性、療癒...） |

**怎麼做（任選）**：
- 自己用 Canva / Figma 設計（免費）
- 找 Fiverr / Pinkoi 接案（NTD 500-2,000）
- AI 生成（Midjourney、DALL-E）再修

**建議 brief**：「給[你的領域]品牌的 logo，色調[你想要的氣氛]，元素可考慮：[3-4 個視覺暗示]，避免[你領域的俗套元素]」

- [ ] 1024×1024 PNG 完成
- [ ] 縮小到 96×96 仍清楚可辨

### 1.2 隱私政策（Privacy Policy）URL

**必填**。需要：
- 公開可訪問的 URL（HTTPS）
- 涵蓋：蒐集什麼資料、為何蒐集、如何使用、如何刪除、聯絡方式

**最快做法**：
- 用 Termly（[termly.io/products/privacy-policy-generator](https://termly.io/products/privacy-policy-generator)）— 免費版能用，輸入幾個資訊產出
- 或 PrivacyPolicies.com — 同類工具
- 公開放在：你個人網站、Notion 公開頁、GitHub Pages、Carrd 等

> ⚠️ **不要直接複製別人的隱私政策**。Meta reviewer 會檢查實際內容是否對應你的 App 行為。

- [ ] 用工具產出草稿
- [ ] 改寫對應「Threads bot 自動回覆留言」的實際資料流
- [ ] 找個地方公開（建議 Carrd 或 Notion 公開頁，免費快速）
- [ ] 取得最終 URL

### 1.3 服務條款（Terms of Service）URL

**強烈建議**（不是必填，但有比沒有好）。可以用同樣工具產生，跟 Privacy Policy 放一起。

- [ ] ToS 草稿
- [ ] 公開 URL

### 1.4 App 詳細描述

200-500 字描述 App 的用途、目標用戶、核心價值。這個會出現在用戶授權畫面。

**範本（請改成你的）**：
> [你的 App 名稱] 是一個輔助 Threads 創作者管理留言互動的工具。
> 服務對象是內容創作者（特別是 [你的領域類型]）。
> 核心功能：自動偵測貼文留言、智能分類（諮詢、感謝、提問、負評）、引導使用者進行更深入的私訊溝通。
> 不主動推送任何商業內容、不蒐集陌生用戶資料、不對外公開個人化建議。

- [ ] 寫好 200-500 字描述
- [ ] 對齊你的品牌定位

### 1.5 App 類別選擇

從 Meta 預設清單選一個。對你的 App 最合適：
- **Productivity & Organization**（生產力／工具）← 推薦
- 或 **Business & Pages**（商務）

- [ ] 確認類別

## 階段 2：每個權限的使用情境說明（總計 5-8 小時）

每個你申請的權限，**都要寫一份**「為什麼我要這個」。每份 200-500 字。

### 2.1 threads_basic
- 為什麼需要：讀取自家 Threads 個人檔案與貼文清單，bot 才知道要監控哪些貼文
- 如何使用：每 5 分鐘拉自家最近 8 則貼文
- 用戶得到什麼：完整的留言管理體驗

- [ ] 寫好說明 + 截圖

### 2.2 threads_content_publish
- 為什麼需要：bot 偵測到留言並判斷可自動回覆後，要呼叫此 API 發回覆
- 如何使用：每則自動回覆呼叫一次
- 用戶得到什麼：及時的留言回應

- [ ] 寫好說明 + 截圖

### 2.3 threads_manage_replies
- 為什麼需要：bot 需要管理（讀取/隱藏）自家貼文下的留言
- 如何使用：偵測到負評時隱藏（可選功能）
- 用戶得到什麼：留言區秩序維護

- [ ] 寫好說明 + 截圖

### 2.4 threads_read_replies
- 為什麼需要：讀取自家貼文的留言內容，才能交給 AI 判斷
- 如何使用：每 5 分鐘拉一次留言
- 用戶得到什麼：留言不漏接

- [ ] 寫好說明 + 截圖

### 2.5 threads_keyword_search（功能 #2 用）
- 為什麼需要：找特定主題的熱門貼文，了解話題趨勢
- 如何使用：每天搜尋預設關鍵字一次
- 用戶得到什麼：內容創作靈感、市場洞察

- [ ] 寫好說明 + 截圖

### 2.6 threads_manage_insights
- 為什麼需要：分析貼文成效、優化內容策略
- 如何使用：每日凌晨拉前一天的 insights
- 用戶得到什麼：數據驅動的內容決策

- [ ] 寫好說明 + 截圖

## 階段 3：示範影片（總計 8-15 小時，最痛苦的一塊）

### 3.1 影片規格

| 項目 | 規格 |
|---|---|
| 長度 | 5 分鐘以下 |
| 解析度 | 1080p 以上 |
| 格式 | MP4 |
| 語言 | 中文可，但**強烈建議加英文字幕**（reviewer 多在美國/印度） |
| 內容 | 完整展示授權流程 + 每個申請權限的使用場景 |

### 3.2 影片腳本（建議結構）

1. **0:00-0:30** 介紹：你的 App 是什麼、解決什麼問題
2. **0:30-1:00** 用戶授權流程：點 Login → 同意 → 跳回
3. **1:00-1:30** threads_basic + threads_read_replies：抓貼文與留言
4. **1:30-2:30** Claude AI 分析 → 自動草擬回覆（截圖或螢幕錄）
5. **2:30-3:30** threads_content_publish：發送回覆 + 看結果
6. **3:30-4:00** threads_keyword_search：搜尋熱門話題
7. **4:00-4:30** threads_manage_insights：每日成效報表
8. **4:30-5:00** 結語：用戶怎麼撤銷授權、資料怎麼處理

### 3.3 工具
- **錄製**：OBS Studio（免費）、Camtasia
- **剪輯**：DaVinci Resolve（免費）、CapCut、Premiere
- **字幕**：CapCut 自動產生 + 手動校正

- [ ] 寫好腳本
- [ ] 錄製
- [ ] 剪輯 + 字幕
- [ ] 上傳到不公開的 YouTube / Vimeo（要給 Meta 看）
- [ ] 拿到不公開分享連結

## 階段 4：測試帳號（總計 1-2 小時）

Meta reviewer 會用這個帳號實際登入測試。

- [ ] 建立**獨立的測試 IG 帳號**（不要用你的主帳號）
- [ ] 名稱類似 `your_app_test`
- [ ] 發 1-2 則測試貼文
- [ ] 在 dashboard「應用程式角色」加為 Threads Tester
- [ ] 把帳號 + 密碼寫在審核資料填寫頁

## 階段 5：商家驗證（最大障礙、總計 2-4 週）

**這是大多數個人開發者卡住的地方**。

### 5.1 你需要一個商業實體（任選一個）

| 選項 | 適合誰 | 成本 | 時間 |
|---|---|---|---|
| **行號**（商業登記） | 個人小規模 | NTD ~1,000 規費 + ~2,000 代辦 | 1-2 週 |
| **有限公司** | 想正式經營 | NTD ~12,000 規費 + ~20,000 代辦 | 2-4 週 |
| **借用親友的公司** | 有信任的親友 | 免費（但有風險） | 1 週 |

> **行號是最便宜路徑**。台北市可去「商業處」或委託會計師代辦。

### 5.2 需要的文件

- [ ] 商業登記證 / 公司登記證影本
- [ ] 稅籍登記
- [ ] 負責人身分證影本
- [ ] 銀行帳戶證明（公司戶或個人戶皆可）
- [ ] 公司地址證明（水電帳單、租賃契約）

### 5.3 在 Meta business.facebook.com 提交驗證

- [ ] 建立 Business Portfolio
- [ ] 連結你的 App 到 Business Portfolio
- [ ] 上傳所有文件
- [ ] 等 Meta 電話 / Email 驗證（會打到負責人手機）
- [ ] 拿到「已驗證」狀態

---

## 階段 6：資料使用驗證（總計 1-2 小時）

- [ ] 進入 App Dashboard → Data Use Checkup
- [ ] 簽署 Standard Contractual Clauses（標準契約條款）
- [ ] 確認用戶刪除帳號時你會清除其資料
- [ ] 確認你不會把資料賣給第三方

---

## 階段 7：提交 + 等審核

- [ ] 進入 Meta App Review 頁面
- [ ] 為每個權限提交「使用情境說明 + 截圖 + 影片連結」
- [ ] 提交測試帳號帳密
- [ ] 點 Submit → 等 Meta 回應（3 天-4 週）

### 常見退件原因（先預防）
- ❌ 影片畫面不清楚 / 沒展示某個權限的場景
- ❌ 隱私政策內容跟實際 App 行為對不上
- ❌ 測試帳號 reviewer 登不進去（OAuth 流程壞了）
- ❌ App 描述跟實際功能不一致
- ❌ 圖示太簡陋 / 像素化

## 時間 + 成本總結

| 階段 | 時間 | 成本 | 備註 |
|---|---|---|---|
| 1-2 個人準備 | 10-18 小時 | NTD 0-2,000（圖示外包） | 隨時可做 |
| 3 影片 | 8-15 小時 | NTD 0 | 自己錄 |
| 4 測試帳號 | 1-2 小時 | NTD 0 | |
| 5 商家驗證 | 2-4 週 | NTD 3,000-30,000 | 最大門檻 |
| 6-7 提交審核 | 1-3 個月 | NTD 0 | 看 Meta |

**完整跑完最少 1 個月、平均 2-3 個月、總成本 NTD 3,000-30,000**。

## 建議推進順序

如果你決定走，**這個順序最有效率**：

```
週 1-2  →  階段 1-2（圖示、文件、權限說明）  ← 個人能完成、零成本
週 2-3  →  階段 3（影片）                  ← 卡腦、預留充裕時間
週 3-4  →  階段 5（商家申請）開始平行進行    ← 等待行號的時間
週 5-6  →  階段 4 + 6（測試帳號、Data Use）  ← 收尾
週 6+   →  階段 7（提交審核 + 等）          ← 多預留 1-2 個月
```

階段 1-2 隨時都能開始，**不用等到要交件才動手**——零成本累積。

---

## 哪些可以「現在就動手準備、不會浪費」

> 即使最後沒走 App Review，這些東西對你的品牌也都用得到：

- ✅ App 圖示 → 也能當你 LINE 官方帳號 / Threads 個人頭像
- ✅ 隱私政策 → 任何商業活動都需要
- ✅ App 描述 → 改一改就是你的服務 EDM 文案
- ✅ 示範影片 → 拆成 IG Reels / Threads 短內容
- ✅ 商家登記 → 開始接諮詢服務、開課程都需要

→ **建議先從這些「即使不交件也有價值」的開始累積**。
